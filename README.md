# «Граф денег»

Локальная объяснимая система исследования обезличенного графа переводов. Она ранжирует клиентов для проверки, показывает структурные роли и мотивы, но не делает выводов о виновности.

## Подготовка и запуск

Требуются Python 3.11+, Node.js 20.19+ и [uv](https://docs.astral.sh/uv/). Установка зависимостей и сборка интерфейса выполняются один раз:

```bash
cd frontend && npm ci && npm run build && cd ..
uv sync --locked --extra dev --no-editable
```

После этого один локальный запуск пересчитывает данные и открывает приложение на `http://127.0.0.1:8000`:

```bash
uv run --locked --no-editable money-graph demo --data data --out artifacts/latest
```

Отдельные команды для пакетного расчёта и просмотра готового запуска:

```bash
uv run --locked --no-editable money-graph analyze --data data --out artifacts/latest
uv run --locked --no-editable money-graph serve --artifacts artifacts/latest
```

`--config path/to/scoring.yaml` у `analyze` и `demo` задаёт другую версию порогов и весов. Без параметра используется `config/scoring.yaml` в исходном проекте или встроенная копия после установки пакета. После изменения Python-кода или сборки frontend переустановите пакет командой `uv sync --locked --extra dev --reinstall-package money-graph --no-editable`, чтобы команда и встроенный интерфейс соответствовали исходникам.

Для сборки переносимого Python-пакета сначала соберите frontend, затем выполните `uv build`. Сборка проверяет `index.html` и упомянутые в нём JS/CSS файлы; отсутствие ресурсов завершает сборку ошибкой. Wheel содержит интерфейс и стандартную конфигурацию. Сборка Python-пакета не запускает npm.

## Роли и пороги

Каждый клиент получает одну основную роль. Система выбирает роль с наибольшим score среди тех, что достигли минимума 0.50; если ни одна роль не достигла порога, ставится `peripheral`. `role_score` описывает соответствие формальному правилу, а не вероятность нарушения.

| Роль | Правило допуска и score |
|---|---|
| `consolidator` | Не менее 3 входящих контрагентов; score взвешивает степень, сумму и число входящих операций, а также охват seed. |
| `transit` | Не seed; есть вход и выход; отношение выходящего оборота к входящему — от 0.80 до 1.20. Score: 70% баланса оборота и 30% FIFO-совместимости за 1–2 дня. |
| `distributor` | Не менее 5 получателей; score объединяет число получателей (50%), исходящие операции (30%) и оборот (20%). |
| `terminal` | Есть вход, нет наблюдаемых исходящих, `depth < 4`, после последнего поступления прошло минимум 2 дня. Score начинается с 0.50 и ограничен 0.75. |
| `coordinator` | Betweenness не ниже 90-го процентиля положительных значений и достижимость от 2+ seed либо связи с 2+ соседними кластерами. Score использует betweenness (50%), охват дополнительных seed (30%) и межкластерный оборот (20%). |
| `peripheral` | Ни одна основная роль не набрала 0.50. Score основан на отрыве лучшей альтернативы от порога; если наблюдение обрезано по глубине или времени, он ограничен 0.49. |

`evidence` содержит измеренные факты для выбранной роли. `why` в топ-листе дополняет эти факты общим priority и тремя наибольшими взвешенными вкладами. Полные правила, формулы, порядок разрешения равенств и ограничения описаны в [методике](docs/methodology.md).

## Результаты

`artifacts/latest` — атомарный указатель на завершённый каталог в `artifacts/.money_graph_runs/`. В нём находятся обязательные `nodes_roles.csv` (все 2 248 клиентов), `clusters.csv` и `top_nodes.csv` (топ-50), а также признаки в Parquet, подробные карточки, мотивы, disruption, sensitivity и `manifest.json`. Manifest содержит версию методики, эффективную конфигурацию с хешем, хеши входа/выхода, версии библиотек, предупреждения и длительности. Старый успешный набор остаётся доступным при неудачной публикации нового.

Каталог `deliverables/` содержит эти три CSV для сдачи вместе с исходным репозиторием. После нового расчёта обновите их одной командой:

```bash
for name in nodes_roles clusters top_nodes; do cp "artifacts/latest/$name.csv" deliverables/; done
```

API доступен на `/api/health`, интерактивная схема — на `/docs`. При открытии приложения показывается новый обзор в тёмной теме; светлая тема переключается в верхней панели. Интерфейс адаптирован для компьютера и телефона и включает поиск по любому `gid`, фильтры и пагинацию, направленный граф 1–2 переходов, карточку клиента с правилами и вкладами priority, операции и дневной график, сообщества, полный постраничный список мотивов, структурную устойчивость, чувствительность весов, AI-ассистента и ссылки на CSV. Фильтры меняют список, но не пересчитывают оценки или окружение. Все JSON-ответы относятся к одному `run_id`; `gid` передаётся строкой из-за точности JavaScript.

## AI-ассистент

Отключён по умолчанию. Для OpenAI скопируйте пример настроек в корень проекта и впишите свой ключ **в `.env`, в строку `MONEY_GRAPH_LLM_API_KEY=`**. Файл `.env` исключён из Git. Не вставляйте ключ в код, браузер или сообщение в чате.

```bash
cp .env.example .env
# Откройте .env в редакторе и заполните MONEY_GRAPH_LLM_API_KEY
set -a
source .env
set +a
uv run --locked --no-editable money-graph demo --data data --out artifacts/latest
```

Пример использует `https://api.openai.com/v1/chat/completions` и модель `gpt-4.1-mini`; при необходимости смените модель на доступную вашему API-проекту. Переменные должны быть загружены **до запуска сервера**. Для другого OpenAI-compatible endpoint задайте свои `MONEY_GRAPH_LLM_URL` и `MONEY_GRAPH_LLM_MODEL`.

Внешнему провайдеру передаются вопрос и выбранный `gid`; модель выбирает только разрешённый тип запроса. Backend проверяет интерпретацию явно указанного или выбранного `gid`, получает факты из текущего запуска, возвращает ограничения и ссылки на карточки или мотивы. Списки ограничены 20 элементами и сообщают число найденных; ограничение поиска мотивов показано отдельно. Ранжирование фактов выполняет сервер, без дополнительного вызова модели. Статус «настроен» означает наличие переменных, а доступность проверяется при запросе. Ответ API содержит статусы `ok`, `needs_clarification`, `unsupported`, `entity_not_found`, `disabled`, `invalid_provider_response`, `provider_unavailable` или `no_data`. Без настроек работают все основные функции и детерминированные объяснения. Локальные тесты с имитацией провайдера не подтверждают реальный сетевой ответ.

## Проверки

```bash
uv run --locked --no-editable ruff check src tests
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 uv run --locked --no-editable pytest -q
cd frontend && npm run build && npm run lint && npm run test && npm run test:e2e
```

Для E2E нужен созданный `artifacts/latest` и Chromium (`npx playwright install chromium`). После изменения Python-кода или интерфейса сначала пересоберите frontend, если меняли его, затем обновите установленный пакет командой `uv sync --locked --extra dev --reinstall-package money-graph --no-editable`. Время полного расчёта измеряйте внешним таймером, включая запись и переключение указателя: `/usr/bin/time -p uv run --locked --no-editable money-graph analyze --data data --out artifacts/latest`. Ограничение ТЗ — 300 секунд на предоставленном наборе.

Проверка 23.09.2026 на предоставленных данных: 52 Python-теста, 2 Vitest-теста и 6 Playwright-сценариев прошли; Ruff и ESLint прошли; `npm audit` сообщил 0 уязвимостей. Полный пересчёт с публикацией занял 49,08 секунды при повторном запуске; хеши всех 11 выходных файлов, включая три CSV, совпали между двумя запусками. Сохранены 2 248 клиентов, 4 840 операций и 19 изолятов. Wheel, собранный через sdist, установлен вне репозитория: стандартная конфигурация, главная страница, JS/CSS и API доступны. Текущий manifest содержит методику `1.2.2` и формат артефактов `4`; завершённые прежние запуски сохранены. Настройки внешнего LLM отсутствовали, поэтому реальный сетевой ответ провайдера не проверялся.

## Смысл результатов и развитие

Исходная выборка ограничена четырьмя переходами от seed, операциями внутри банка и порогом 5 000 KZT. Даты точны до дня, входящие операции seed неполны, отсутствие исходящих на depth=4 ничего не доказывает. Пути от seed и совпадения сумм по времени — аналитические сигналы, а не подтверждение происхождения конкретных денег. Подробные определения и формулы: [методика](docs/methodology.md), [архитектура](docs/architecture.md), [демо](docs/demo.md), [инструкции для агентов](agentic.md).

Для миллиона узлов потребуется колонночная обработка, компактный графовый движок, приближённая центральность, ограниченные seed-запросы и подграфы по запросу. Эта реализация рассчитана на предоставленный локальный набор и не включает банковские доступы, аудит пользователей или промышленное развёртывание.
