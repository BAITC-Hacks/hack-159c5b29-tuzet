# agentic.md — правила разработки «Графа денег»

## Конечная цель

Один локальный запуск читает исходные Parquet, за 300 секунд или быстрее рассчитывает объяснимую модель, сохраняет `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv` и открывает веб-интерфейс, где можно за минуту объяснить результат по любому `gid`. Роль, мотив, приоритет и evidence — отдельные сущности. Полная версия показывает временные мотивы, устойчивость сети, чувствительность рейтинга и опционального AI-ассистента.

## Источники и стек

1. `Document 6.pdf` — ТЗ; `data/` и `starter/` — неизменяемые исходные материалы.
2. `config/scoring.yaml` — исполняемые пороги, веса и период; `src/money_graph/scoring.yaml` — копия для установленного пакета. При изменении параметров обновлять обе копии.
3. `docs/methodology.md` — смысл формул и ограничения; `docs/architecture.md` — границы модулей.

Python 3.11, pandas/PyArrow, NumPy, NetworkX, SciPy, FastAPI/Pydantic; React/TypeScript/Vite, Cytoscape.js, Recharts. Проверки: pytest, Ruff, Vitest, Playwright. Зависимости фиксированы `uv.lock` и `frontend/package-lock.json`. Оформление — существующий CSS; Tailwind не добавляется ради формального совпадения со старым планом.

## Аналитические инварианты

- Сначала добавлять **все** `nodes.gid`, затем рёбра. Не удалять совпадающие строки операций: внутренний `transaction_id` не является банковским ID.
- Проверять типы, пропуски, даты, depth, принадлежность `gid`, суммы и количество транзакций против рёбер. Денежные агрегации и FIFO выполнять в целых тиынах; расхождение агрегатов — максимум один тиын без относительного допуска.
- Основной граф направленный. Ненаправленная проекция применяется только для Louvain. В betweenness сумма не является расстоянием.
- Даты известны до дня. Однодневный порядок неизвестен. Достижимость от seed — структурная связь, а не доказательство происхождения суммы. Независимые ветви и число достижимых seed не смешивать.
- Входящий поток seed неполон. Граница `depth=4` и конец периода цензурируют наблюдение. `terminal` — наблюдаемая конечная точка. `coordinator` — структурная гипотеза, не «организатор».
- `role_score` — соответствие правилу, не вероятность вины. Не утверждать о преступлении, не восстанавливать личные данные и не подставлять ответы для конкретных `gid`.
- Веса и пороги читать из проверенной конфигурации. Нормализация положительных признаков — процентиль с усреднением равных, нули — 0. Вклады priority хранить без округления. Multi-seed не добавляет повторный бонус к typology.
- Конфигурацию проверять типизированной моделью до чтения Parquet: неизвестные поля, нецелые дни, `bool` вместо числа и неконечные веса отклонять. Исходная и упакованная стандартные конфигурации должны быть смыслово равны.
- Мотив содержит реальные рёбра, статус временной совместимости и подтверждающие внутренние ID операций. Ограниченный поиск отмечать `truncated`; отсутствие в усечённом результате не означает отсутствие мотива.
- Временное подтверждение цикла искать со всех начальных вершин и выбирать по датам и ID операций. Повторения требуют разных дат начала и не используют одни операции повторно; пересечение календарных дней допустимо. Совместимые суммы складывать в целых тиынах.

## Контракты результатов

`nodes_roles.csv`: `gid,role,role_score,cluster_id,priority_score,evidence`.
`clusters.csv`: `cluster_id,n_nodes,n_seed,sum_kzt_internal,top_gids,hypothesis`.
`top_nodes.csv`: `rank,gid,role,priority_score,why`.

Роли: `consolidator`, `transit`, `distributor`, `terminal`, `coordinator`, `peripheral`. CSV сохраняет int64 `gid`; JSON API отдаёт все `gid` строками. Краткий evidence содержит рассчитанные числовые факты и не превышает 200 символов. Полная карточка хранит правила, пороги, измеренные признаки, все scores, пять вкладов, пути, мотивы и ограничения.

## Границы приложения и сохранность

- Аналитика не зависит от HTTP, UI и LLM. API закрепляет один завершённый запуск; карточка не пересчитывает граф. UI только показывает результаты API.
- Публиковать новый набор через отдельный каталог запуска и атомарный указатель `latest`. Исходные данные, корень проекта и посторонний непустой каталог не заменять. Сбой не должен уничтожать предыдущий запуск.
- В manifest сохранять полную конфигурацию и хеш, хеши входа/выхода, версии, предупреждения, статусы и время фаз.
- Все JSON-артефакты должны проходить строгую сериализацию без `NaN`/`Infinity`. При сбое прежний завершённый запуск остаётся доступным.
- AI отключён по умолчанию; ключи только в окружении. Модель выбирает ограниченный тип вопроса, backend формирует факты и числа из артефактов. AI не меняет аналитику. При недоступности провайдера обычный поиск остаётся доступным.
- Собранный wheel должен содержать frontend. При отсутствии `index.html` или ресурсов сборка завершается ошибкой. В интерфейсе любой мотив клиента доступен через постраничный список.

## Порядок работы агента

1. Прочитать этот файл и относящуюся к задаче методику, определить проверяемый критерий готовности.
2. Сохранять исходные данные и чужие изменения; не менять смысл CSV/API и метрик молча.
3. Добавлять адресные тесты для финансовых расчётов, правил и регрессий; не писать тесты, повторяющие реализацию.
4. Выполнить Ruff, pytest, сборку и тесты frontend, затем реальный запуск для изменений pipeline. Различать автоматическую и ручную проверку.
5. Обновить документацию и честно сообщить о непроверенных частях.

## Definition of Done

Все 2 248 клиента и 4 840 операций сохранены. Три CSV валидны, топ содержит минимум 20 строк. Изоляты и граничные узлы обработаны. Любой `gid` находится в браузере, направленные связи, операции, роль, пять вкладов priority, мотивы и ограничения открываются. Полный расчёт с публикацией укладывается в 300 секунд. Структурные эксперименты и 10 сценариев чувствительности доступны. Запуск после сборки frontend работает одной командой. AI без ключа отключён; его реальное подключение обозначается отдельно от теста с имитацией провайдера.
