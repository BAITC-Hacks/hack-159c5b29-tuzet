# Архитектура

```text
Parquet → ingestion (тиыны, контракт) → DiGraph + операции
        → признаки, Louvain, seed reach, FIFO
        → мотивы → роли → priority → evidence
        → проверка CSV → неизменяемый каталог запуска → указатель latest
        → FastAPI (закреплённый run_id) → React/Cytoscape/Recharts
                                   ↘ опциональный AI intent parser
```

`ingestion.py` проверяет вход и конфигурацию; `features.py` строит граф и признаки; `temporal.py` сопоставляет операции; `motifs.py` ищет структуры; `scoring.py` присваивает роли и приоритет; `evidence.py` создаёт объяснения; `disruption.py` проводит структурные эксперименты; `exports.py` проверяет и публикует результаты. `analytics.py` только соединяет этапы. Эти модули не зависят от API. FastAPI читает готовый набор при старте процесса. Для переключения на новый запуск сервер перезапускают; каждый JSON-ответ содержит `run_id`. Указатель `latest` переключается атомарно после записи и проверки артефактов. Фронтенд раздаётся FastAPI на том же локальном адресе. Внешний провайдер не участвует в расчёте и не получает прямой доступ к файлам или коду.

Опциональный ассистент получает вопрос и выбранный `gid` как контекст, а модель возвращает только намерение по проверяемой Pydantic-схеме. Backend сверяет `gid` из вопроса или интерфейса, читает факты одного закреплённого запуска и сам сортирует результаты. Ответ содержит ссылки на факты, ограничения, общее число найденных и флаги усечения выдачи и поиска. Передача фактов обратно провайдеру для ранжирования не используется. При смене `run_id` запрос отклоняется до вызова модели; при недоступности модели расчётные страницы остаются доступными.
